# 낌새 글 게시 파이프라인

원고 위치: `C:\Users\사라띠\Documents\원고대기\낌새\` (비공개 저장소. 이미지 원본 PNG는 그 안 `img/`)
저장소: `C:\Users\사라띠\Documents\kkimsae\` (공개 — 원고 md·원본 PNG는 절대 여기 두지 않는다)
디자인·문구 규칙: `Documents/기록/낌새_디자인규칙.md`, `Documents/글쓰기규칙.md`, `Documents/기록/원고작업_규칙.md`
아래 단계를 **순서대로 전부** 수행한다. 하나라도 건너뛰지 않는다.

## 0단계: 사전 점검
1. `git pull` (kkimsae와 Documents 둘 다) — 회사 PC·노트북을 오가므로 반드시 최신화
2. 원고 머리말 확인: `title / slug(영문 소문자·하이픈) / category(경제·금융|이맘때|게임|일상) / tags / description(80~125자) / images(원고 폴더 기준 상대경로)`. 카테고리 주소는 순서대로 `/money/ /season/ /game/ /daily/`. 본문의 `![alt](img/…)` 줄과 images가 짝이어야 한다
3. **독립 재검증이 끝났는지 확인** — 수치·날짜·규정을 별도 에이전트가 출처와 대조한 기록이 없으면 게시하지 않는다(인수인계 4절)
   - **게임·e스포츠·스포츠 글은 기준을 한 단계 높인다**(9/7 운영자 지적 — "팀·장소·경기 방식·가격·일정·시작 시각이 정확해야 한다"). 원고 전에 사실표를 만들고 항목마다 **공식 1차 출처**(리그·팀·티켓 판매처 공지)를 붙인다: ① 대진 팀·시드 ② 장소(경기장 이름·주소) ③ 경기 방식(단판/3판2선/5판3선, 라운드 구조) ④ 티켓 가격·좌석 등급·판매처·오픈 시각 ⑤ 일정·시작 시각(주중/주말, 그해 편성) ⑥ 중계 채널. 나무위키·블로그만 있는 항목은 "공지 기준·예매 시 확인"으로 한정하거나 뺀다. 재검증 에이전트 프롬프트에 이 6항목을 그대로 넣는다
4. 이미지 승인 확인 — 운영자가 "그림 OK" 한 뒤에만 진행. 실사 규칙은 `기록/이미지생성_진행상황.md` ★ 실사 이미지 규칙 절(글당 2장, 손가락·글자·문손잡이·지폐 검수)
   - **e스포츠·유명인·특정 장소가 주제면 AI 이미지 대신 실제 사진**(9/7 운영자 지시). 출처는 위키미디어 공용(commons.wikimedia.org)의 CC BY / CC BY-SA 사진만 — API로 `LicenseShortName`·작성자 확인 후 내려받아 원고 `img/`에 두고, 원고에 `![alt](img/파일 "캡션")` 문법으로 **작가·출처 링크·라이선스 링크**를 캡션에 적는다(figcaption으로 렌더). 라이엇·언론사·팀 공식 사진은 저작권 허락이 없으니 쓰지 않는다. 캡션 예: `사진: 홍길동, [위키미디어 공용](파일 페이지 URL), [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)`
   - **URL에 괄호가 있으면 `%28` `%29`로 바꿔 쓴다**(예 `File:FluShot_%2837127923433%29.jpg`). 마크다운 변환기가 `)`에서 링크를 끊어 9/10 독감·윈터타이어 캡션 링크가 깨졌었다. 게시 전 검사에 `href="https://commons…"`가 `.jpg"`로 끝나는지 grep
   - **접종·시술 사진은 의료인 손에 반지·시계 등 액세서리가 없는지 본다**(9/10 운영자 기각 — "의료인은 주사 놓을 때 액세서리를 끼지 않는다")

## 0-1단계: 토큰 절감 규칙 (2026-09-11 운영자 지시 — 품질은 그대로, 턴과 출력만 줄인다)
연말정산 미리보기 세션 실측: 낭비의 절반이 ①`ctx_search` 결과가 같은 카드뉴스 본문을 질의마다 3KB씩 6번 반복 출력 ②2차 출처가 이미 국세청 발표를 직접 인용했는데 1차를 더 찾겠다고 게시판 검색 8턴(전부 실패) ③재검증 에이전트가 정책브리핑 게재일을 개통일로 오인해 거짓 불일치 → 추가 추적.
1. **출처 본문은 `ctx_search` 대신 `ctx_execute`로 뽑는다** — fetch 뒤 정규식으로 필요한 문장만 `console.log`(40줄 이내). `ctx_search`를 쓸 땐 `limit: 1`, 같은 출처엔 질의 1개
2. **출처 충분 기준**: 1차 1건 일치, 또는 기관 발표를 직접 인용한 2차("국세청은 오늘 ~ 밝혔다") 1건 + 다른 2차 1건. 이 기준을 채우면 더 찾지 않는다. 추가 추적은 **2턴까지**, 실패하면 사실표 "쓰지 않은 것"에 적고 본문을 한정 표현으로 낮춘다
3. **재검증 에이전트 프롬프트에 고정 문구**: "정책브리핑·기사 게재일은 개통일·시행일이 아니다. 판정표 전체 대신 **불일치·추론 항목만** 보고하고 일치는 개수만 적어라"
4. **규칙 파일은 세션당 1회, 필요한 절만** — 인수인계는 §4·§5만, 이 SKILL은 0~3단계만. `WebSearch`는 URL 찾기 2회까지, 본문은 `ctx_execute`
5. 원고는 처음부터 문장 70자·"~습니다" 3연속 금지를 지켜 readcheck 수정 라운드를 0~1회로

## 1단계: 계획표 → 운영자 확인
```
node tools/publish.js <원고.md> --dry
```
제목·주소·카테고리·게시일·이미지·오늘 게시 편수가 출력된다. **이 계획표를 운영자에게 보여주고 확인을 받은 뒤** 2단계로 간다.
하루 상한은 도구가 강제한다(같은 게시일 2편이면 중단). **이미 2편이면 여기서 멈추고 "내일 올릴까요?"라고 묻는다.** 운영자가 한도 초과를 지시해도 리듬 규칙을 상기시키고 재확인받는다. 우회 옵션은 없다.

## 2단계: 생성
```
node tools/publish.js <원고.md>            # 새 글
node tools/publish.js <원고.md> --update   # 이미 게시된 글 수정 (게시일 유지, 수정일 오늘)
```
하는 일: 이미지 → 폭 1200 webp 300KB 이하로 `/img/슬러그-NN.webp` · 본문 md → `/{카테고리}/{슬러그}.html` · `tools/posts.json` 갱신 · `buildlist.js`(홈·카테고리 목록·이어서 읽을 글·sitemap.xml·feed.xml) 실행.
**본문 문구·수치는 원고 그대로.** 고칠 게 보이면 운영자에게 묻고 원고를 고친 뒤 다시 실행한다. HTML을 손으로 고치지 않는다.

## 3단계: 배포 전 검사
- `node tools/readcheck.js {카테고리}/{슬러그}.html` — 긴 문장·AI투·금지 표현 경고를 운영자에게 보고(자동 수정 금지)
- 내부 링크 전수: 새 글과 갱신된 파일의 `href="/…"`가 모두 실제 파일인지 확인. 깨진 링크가 있으면 **배포 중단**
- 메타 설명(description)이 본문에 그대로 반복되지 않았는지 확인
- 이미지: `img/` 파일 존재·300KB 이하·alt 있음·width/height 있음
- 로컬 확인: 브라우저 도구로 `.claude/launch.json`의 `kkimsae`(8789)를 열어 375px·1280px에서 글 화면 확인(이미지가 본문 폭을 넘지 않는지, 표가 가로 스크롤 상자 안에 있는지, 콘솔 오류 0)
- `node tools/buildlist.js --check` 통과(pre-commit 훅도 같은 검사를 한다)

## 4단계: 커밋·푸시
- 한글 커밋 메시지. 예: `글 게시: 실업급여 계산 방법 (목록·sitemap·feed 반영)`
- **푸시까지 완료해야 실제 반영.** 훅이 실패하면 원인을 고치고 다시 커밋한다(`--no-verify` 금지)

## 5단계: 실사이트 확인 → IndexNow
1. 1~2분 뒤 `https://kkimsae.com/{카테고리}/{슬러그}.html`이 **200**을 돌려주는지 확인(curl -sI). 이미지 주소도 200
2. 200 확인 뒤에만 `node tools/indexnow.js https://kkimsae.com/{카테고리}/{슬러그}.html` — 응답 200/202면 네이버·빙 접수. 403 키 불일치, 422 키 파일 위치·호스트 문제. 결과 코드를 보고에 남긴다. 수정 글(`--update`)도 다시 보낸다
3. 구글은 API가 없다. 운영자가 "색인 요청도"라고 하면 클로드 인 크롬으로 서치콘솔 → kkimsae.com 속성 → URL 검사 → "색인 생성 요청". 로그인은 하지 않는다

## 6단계: 마무리
1. 원고 md와 이미지 원본을 `원고대기/낌새/` → `원고완료/낌새/`로 이동(Documents 저장소에 커밋·푸시)
2. `기록/블로그_진행상황.md` 낌새 절에 게시 한 줄, 세션 끝에 `기록/작업로그.md` 5줄
3. 운영자에게 보고: 게시 URL, readcheck 결과, IndexNow 응답 코드, 확인 못 한 것

## 페이지(소개·개인정보처리방침·연락) 고칠 때
원고는 `원고대기/낌새/페이지_*.md`. 고친 뒤 `node tools/page.js <페이지.md>` → 커밋·푸시.

## 틀(머리·메뉴·사이드바·바닥·CSS 구조)을 바꿨을 때
1. `node tools/scaffold.js` (홈·카테고리 4·검색·404·robots 재생성) → 2. 글마다 `node tools/publish.js 원고완료/낌새/<원고>.md --rebuild` (게시일·수정일 유지, `--update`는 수정일이 바뀌니 내용 수정 때만) → 3. `node tools/buildlist.js` → 4. 페이지 3종 `page.js` → 5. 로컬 375·1280 확인 → 커밋·푸시. 옛 틀 글이 남아 있으면 buildlist가 "AUTO:SIDE 마커가 없음" 주의를 낸다.
